# Cluster P3.3 — Remote MCP Gateway deployment contract

Status: **design and local preparation only**. No public HTTPS MCP endpoint has been deployed.

## Intended topology

ChatGPT / supported remote MCP client -> HTTPS MCP endpoint (OAuth or equivalent client authentication) -> per-user relay -> outbound authenticated tunnel from Cluster Local Agent -> Cluster browser editor adapter.

Do not expose port 43879, the pairing token, or a localhost WebSocket directly to the Internet. A GitHub Pages site cannot host a persistent MCP backend.

## Minimum security requirements before enabling remote actions

1. HTTPS-only remote MCP with authentication tied to a user and device, per-device revocation and short-lived grants.
2. The local Agent initiates the outbound connection. Never port-forward 43879 or embed pairing tokens in public URLs.
3. Read-only discovery first; file writes require workspace-scoped approval and version checks.
4. Terminal commands require explicit per-command confirmation; deny arbitrary commands by default.
5. Bind browser editor session to the local Agent with authenticated messages, origin validation, and task IDs.
6. Record task lifecycle (queued/running/waiting_approval/completed/failed/interrupted) and audit logs.
7. Handle disconnection, replay protection, rate limits, timeouts and stale session revocation.
8. MCP server must support the protocol expected by the chosen remote client (HTTP transport, initialize, tools/list, tools/call and authentication).

## What is implemented now

- Loopback-only authenticated GET /mcp/status and /mcp/tasks in the local Agent.
- Read-only MCP stdio adapter for compatible **local** AI clients.
- AI Agent status panel with local BIND and connection guide.

## Not yet implemented

- Hosted HTTPS MCP service, OAuth/remote connector registration, secure tunnel, browser editor tool bridge.
- End-to-end ChatGPT-to-Cluster tool calls.
- Automatic file editing or PowerShell execution.

## Acceptance criteria for a future P3.3 remote implementation

- A remote client can discover the authenticated MCP endpoint without any local token disclosure.
- A remote client can invoke cluster.get_status for the paired device.
- Disconnect and revoke terminate access; another user cannot reach the device.
- No write or terminal operations are exposed until explicit authorization is implemented.
